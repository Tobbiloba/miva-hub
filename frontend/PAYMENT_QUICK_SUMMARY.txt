ASKLY — PAYMENTS & BILLING (current system)
===========================================

Provider: Paystack (NGN). All amounts are stored and sent in KOBO
(₦1 = 100 kobo), including columns named *_ngn.

PRICING — single source of truth: src/lib/billing/plans.ts
  Individual (students):
    ASKLY_MONTHLY  ₦3,000 / month   (300000 kobo, Paystack interval monthly)
    ASKLY_YEARLY   ₦30,000 / year   (3000000 kobo, Paystack interval annually)
  University (org) seats, prepaid one-time charge:
    ₦2,000 / seat / month, ₦20,000 / seat / year
  The subscription_plan DB rows (migration 0033) must match plans.ts;
  checkout refuses to charge (503 + log) if they drift.

WHO PAYS / WHO HAS ACCESS — src/lib/billing/rules.ts decidePaidAccess
  1. Non-students (faculty, admin, super_admin) → always allowed
  2. Student in free trial (user.trial_ends_at > now) → allowed
  3. Student with own active subscription → allowed
     (status active/trialing and current_period_end >= now; a renewing
      subscription gets a 48h grace window past period end for the
      renewal webhook to land; past_due/cancelled get none)
  4. Student holding a university seat → allowed
     (seat rule: active-enrollment students in signup order; the first
      N = sum of seat limits of the university's currently-covering
      subscriptions are covered)
  5. Otherwise paywalled
  Pages: (chat)/layout.tsx and student/layout.tsx redirect to /billing.
  APIs: checkPaidAccess() → HTTP 402 {error, code: "PAYMENT_REQUIRED"}
        (src/lib/billing/access.ts), on every AI/paid-content route.

STUDENT FLOW
  /billing (or /pricing) → POST /api/billing/checkout {plan}
    → pending payment_transaction row (OUR record of payer + plan)
    → Paystack checkout → redirect to /billing/callback?reference=…
    → POST /api/billing/verify verifies with Paystack and applies the
      payment (same code as the webhook) → success only when active.
  Renewals: Paystack charges automatically; webhooks extend the period.
  Cancel: POST /api/billing/cancel → disables the Paystack subscription
    FIRST (errors are surfaced, never swallowed), then marks
    cancel_at_period_end. Access continues until current_period_end.
  Profile billing tab: GET /api/billing/details, GET /api/billing/manage-link
    (Paystack card-update page), POST /api/billing/cancel.

UNIVERSITY FLOW (admin)
  POST /api/admin/billing/checkout {seats, interval} → pending
  university_subscription row stamped with the Paystack reference →
  Paystack → GET /api/admin/billing/callback. Activation (callback or
  webhook) finds the row by OUR reference (never Paystack metadata),
  checks it belongs to the admin's university, and requires
  amount paid >= seat_limit × price_per_seat. Early renewals stack.
  Super admins can comp seats: /api/super-admin/universities/[id]/subscription.

WEBHOOK — POST /api/webhooks/paystack (src/lib/billing/individual.ts)
  Signature: HMAC-SHA512 of raw body with PAYSTACK_SECRET_KEY.
  Idempotency: webhook_event.event_key = sha256(raw body), UNIQUE.
    already processed → 200 no-op; recorded but failed → reprocessed.
  Responses: 200 for processed/duplicate/ignored; 500 only on real
    failure (so Paystack retries).
  charge.success        org seat payment, or individual initial/renewal
                        charge: amount+currency checked against the plan
                        row, period extended, receipt emailed exactly once
  subscription.create   stores SUB_ code + email token, aligns period
  invoice.update (paid) extends period from Paystack dates
  invoice.payment_failed → past_due (access ends)
  subscription.not_renew / subscription.disable → non-renewing; access
                        is NOT cut — it lapses at current_period_end
  Period math: new end = max(existing end, next_payment_date or
  paid_at + interval) — idempotent and order-independent.
  One subscription row per user: upserts under a per-user advisory lock.

SETUP
  1. Apply migrations (incl. 0033 plans, 0040 webhook event_key).
  2. pnpm tsx scripts/setup-paystack-plans.ts  (creates Paystack plans
     from plans.ts and writes plan codes to subscription_plan)
  3. Paystack dashboard webhook URL: https://<host>/api/webhooks/paystack
  Env: PAYSTACK_SECRET_KEY (live key in production — startup fails on
  sk_test unless PAYSTACK_ALLOW_TEST_KEY=true), NEXT_PUBLIC_APP_URL
  (required in production; Paystack callbacks and email links).
